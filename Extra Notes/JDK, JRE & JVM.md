In the Java ecosystem, **JDK**, **JRE**, and **JVM** are nested layers that allow you to create and run programs.
These are ==the three core foundational pillars of the Java platform architecture==. They are hierarchically structured where the **JDK contains the JRE**, and the **JRE contains the JVM**.

| Who are you?                | What you need |
| --------------------------- | ------------- |
| Developer writing Java code | **JDK**       |
| User running a Java app     | **JRE**       |
| The engine executing Java   | **JVM**       |

**Understanding these concept helps you:**
- Know what to install for what purpose
- Debug "class not found" errors
- Understand how Java achieves platform independence
- Explain Java's architecture confidently
- Make smart decisions in production deployments

```
┌─────────────────────────────────────────────────────────┐
│                        JDK                              │
│  ┌───────────────────────────────────────────────────┐  │
│  │                      JRE                          │  │
│  │  ┌─────────────────────────────────────────────┐  │  │
│  │  │                   JVM                       │  │  │
│  │  │  ┌─────────────┐  ┌──────────┐  ┌───────┐   │  │  │
│  │  │  │ Class Loader│  │Execution │  │ Memory│   │  │  │
│  │  │  │  Subsystem  │  │  Engine  │  │ Areas │   │  │  │
│  │  │  └─────────────┘  └──────────┘  └───────┘   │  │  │
│  │  └─────────────────────────────────────────────┘  │  │
│  │  + Java Standard Libraries (java.util, java.io...)│  │

JVM = engine that RUNS bytecode.
JRE = JVM + libraries needed to RUN Java programs.
JDK = JRE + tools needed to DEVELOP Java programs.
```

# JVM - Java Virtual Machine
JVM means **Java Virtual Machine**. This is the ==engine inside the JRE==. The JVM takes the universal bytecode generated by the compiler and translates it to the fly into machine ==specific code (0 and 1)== for your specific operating system (Windows, Mac, Linux) as computer doesn't understand java codes directly. The JVM is what makes Java's *"Write Once, Run Everywhere"* philosophy possible.

**Key responsibilities:**
- Load `.class` files
- Verify bytecode (security)
- Execute bytecode
- Manage memory (Garbage Collection)
- Provide runtime environment
- Platform independence layer

### Platform Independence - Write Once Run Anywhere

**Without JVM (C/C++):**
```
┌──────────────┐     compile      ┌──────────────────┐
│  MyApp.c     │ ──────────────►  │ MyApp.exe        │
└──────────────┘  (for Windows)   │ Windows only ❌  │
                                  └──────────────────┘
```

**With JVM:**
```
┌──────────────┐                 ┌──────────────────┐
│  MyApp.java  │                 │  MyApp.class     │
└──────────────┘                 │  (bytecode)      │
       │                         └──────────────────┘
       │  javac                         │
       └──────────────────────────────► │
                                        │
                        ┌───────────────┼────────────────┐
                        ▼               ▼                ▼
                 ┌─────────┐    ┌─────────────┐   ┌──────────┐
                 │Windows  │    │   macOS     │   │  Linux   │
                 │   JVM   │    │    JVM      │   │   JVM    │
                 └─────────┘    └─────────────┘   └──────────┘
                      ✅               ✅               ✅
                 Same bytecode, different JVMs = runs everywhere!
```

### What is Bytecode?
Bytecode is an intermediate, compact, binary representation of source code compiled for a virtual machine (VM) rather than direct hardware execution.
**Java Bytecode:** Compiled Java `.class` files.

#### How Bytecode works?
When you compile Java, it does **NOT** become machine code directly. It becomes **bytecode**. A universal intermediate format. Bytecode is stored in `.class` files (JAVA). Any machine with a JVM can run that `.class` file.

Modern JVMs use an approach called **Tiered Compilation** to balance quick startup speeds with optimized peak performance:

1. **Initial Phase**: When a Java app starts, the **Interpreter** executes everything to ensure the system is up and running immediately.

2. **Profiling Phase**: While running, the **Profiler** checks internal counters to see which functions are being heavily reused.

3. **Compilation Phase**: Once a specific threshold is hit, that chunk of code is passed to the JIT Compiler**.

4. **Optimization Phase**: The JIT compiler optimizes the instructions (using techniques like _method inlining_ or _loop unrolling_) and saves them as native instructions. The JVM uses this pre-compiled machine code for all future invocations.

# JRE - Java Runtime Environment
JRE means **Java Runtime Environment**. This is the environment ( like `System`, `String`, `Math`, etc. ) required to ==run a java application==. Used by **end users** who just want to **run** Java applications. It contains core libraries and the JVM, but it does not contain development tools like the compiler.

JRE = JVM + Java Standard Class Libraries.

It provides everything needed to RUN Java applications, does NOT include development tools (no javac).
```
Contents:
├── JVM (runs bytecode)
├── java.lang     → String, Integer, Object, Math...
├── java.util     → List, Map, Scanner, Arrays...
├── java.io       → File, InputStream, BufferedReader...
├── java.nio      → modern I/O, NIO2...
├── java.net      → Socket, URL, HttpClient...
├── java.sql      → JDBC, Connection, ResultSet...
├── java.math     → BigDecimal, BigInteger...
├── java.time     → LocalDate, LocalDateTime...
├── java.security → encryption, certificates...
└── javax.*       → extended APIs
```
**Note:** Java 11+ → JRE is bundled INTO JDK, Separate JRE download discontinued! Use JDK even for runtime.

# JDK - Java Development Kit
JDK means **Java Development Kit**. This is the complete toolbox for developers. It includes tools (**javadoc**, **jar**, **jdb**) for writing and compiling code, most importantly the compiler (`javac`). The compiler takes your raw Java code (`.java` files) and translates it into an intermediate language called **bytecode** (`.class` files). Used by **developers** who **write and compile** Java.

**Note:** If you are building a new Java program to distribute to everyday users, the everyday users only need to _run_ the program, not build or modify it. Providing just the JRE gives them the JVM and the core libraries they need, without the extra baggage of the development tools found in the JDK.

JDK = JRE + Development Tools

Everything you need to DEVELOP, COMPILE, and RUN Java.
```
JDK Tools:
├── javac     → compiler (.java → .class)
├── java      → JVM launcher (run .class files)
├── jar       → create/manage JAR archives
├── javadoc   → generate HTML documentation
├── jdb       → command-line debugger
├── jshell    → interactive REPL (Java 9+)
├── jps       → list running Java processes
├── jmap      → heap memory map
├── jstack    → thread dump
├── jstat     → JVM statistics
├── jconsole  → GUI monitoring tool
├── jlink     → create custom runtime image (Java 9+)
└── jpackage  → create native installers (Java 14+)
```
